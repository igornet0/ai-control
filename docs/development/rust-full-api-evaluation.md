# Оценка полного переноса API с FastAPI на Rust (опциональная фаза)

Цель «убрать Python из runtime целиком» — **не** модульный перенос, а новый проект поверх уже выделенных sidecar-ов.

## Когда имеет смысл

- Большая доля времени уходит не в sidecar-ы, а в **сам HTTP + ORM-слой** на Python, и команда готова инвестировать в **Axum/Actix + sqlx/SeaORM** с нуля.
- Есть требования по **единому бинарнику**, жёсткой изоляции памяти или длительному масштабированию на CPU без GIL.

## Рекомендуемый порядок

1. Завершить вынос горячих путей в `rust/*` (см. [`rust-migration-hotspots.md`](rust-migration-hotspots.md)).
2. Стабилизировать **контракты** между фронтом и API (OpenAPI как контракт).
3. Поднять **прокси-слой** или BFF на Rust, который пересылает часть маршрутов в Python, пока миграция идёт блоками.
4. Только после 80% трафика на Rust — отключать Python API.

## Риски

- Параллельная бизнес-логика в двух языках без parity-тестов.
- Миграции Alembic и модели домена придётся **переосмыслить** в Rust-экосистеме или оставить «migration-from-Python-only».

До явной продуктовой цели разумнее оставить **гибрид**: FastAPI + Rust sidecars.
