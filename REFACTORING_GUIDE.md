# AI Control System - Refactoring Guide

## Обзор изменений

Проект был рефакторирован с применением принципов Clean Architecture и Domain-Driven Design (DDD). Новая структура обеспечивает лучшую поддерживаемость, тестируемость и масштабируемость.

## Ключевые изменения

### 1. Применение Clean Architecture

- **Доменный слой** (`src/domain/`) - содержит бизнес-логику, независимую от внешних технологий
- **Слой приложения** (`src/application/`) - содержит use cases и координацию доменных объектов
- **Инфраструктурный слой** (`src/infrastructure/`) - содержит реализации интерфейсов
- **Слой представления** (`src/presentation/`) - содержит API контроллеры и веб-интерфейс

### 2. Domain-Driven Design

- **Домены** организованы по бизнес-контекстам
- **Сущности** содержат бизнес-логику и валидацию
- **Репозитории** абстрагируют доступ к данным
- **Use Cases** реализуют бизнес-сценарии

### 3. Улучшенная конфигурация

- **pyproject.toml** - обновлен с правильными зависимостями и настройками
- **pre-commit** - настроен для автоматической проверки кода
- **Структурированное логирование** - JSON формат с контекстом
- **Типобезопасные настройки** - Pydantic для валидации конфигурации

### 4. Новая структура тестов

- **Unit тесты** - тестирование отдельных компонентов
- **Интеграционные тесты** - тестирование взаимодействия компонентов
- **E2E тесты** - тестирование полных пользовательских сценариев

## Как использовать новую структуру

### 1. Запуск приложения

```bash
# Установка зависимостей
pip install -e .

# Запуск в режиме разработки
python -m src.main

# Или через uvicorn
uvicorn src.main:app --reload --host 0.0.0.0 --port 8000
```

### 2. Запуск тестов

```bash
# Все тесты
pytest tests_new/

# Unit тесты
pytest tests_new/unit/

# Интеграционные тесты
pytest tests_new/integration/

# С покрытием
pytest tests_new/ --cov=src --cov-report=html
```

### 3. Проверка качества кода

```bash
# Форматирование кода
black src/ tests_new/

# Сортировка импортов
isort src/ tests_new/

# Линтинг
flake8 src/ tests_new/

# Проверка типов
mypy src/

# Pre-commit hooks
pre-commit run --all-files
```

### 4. Добавление нового домена

1. Создать структуру домена:
```bash
mkdir -p src/domain/new_domain/{entities,value_objects,repositories,services}
```

2. Создать сущности в `src/domain/new_domain/entities/`
3. Создать репозитории в `src/domain/new_domain/repositories/`
4. Создать use cases в `src/application/use_cases/new_domain/`
5. Создать DTO в `src/application/dto/`
6. Создать API контроллеры в `src/presentation/api/controllers/`
7. Написать тесты в `tests_new/`

## Преимущества новой архитектуры

### 1. Поддерживаемость

- Четкое разделение ответственности
- Легко понимать и изменять код
- Меньше связанности между компонентами

### 2. Тестируемость

- Каждый слой можно тестировать изолированно
- Легко создавать моки для внешних зависимостей
- Высокое покрытие тестами

### 3. Масштабируемость

- Легко добавлять новые домены
- Возможность разделения на микросервисы
- Независимое развитие компонентов

### 4. Качество кода

- Автоматическая проверка стиля кода
- Типобезопасность с MyPy
- Структурированное логирование
