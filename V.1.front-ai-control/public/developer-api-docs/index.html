Developer API

Внешний REST API для загрузки данных в модели AiControl, управления источниками и работы с ассетами. Аутентификация — API-ключ (X-API-Key).

Два сервиса

СервисНазначениеАутентификация
Control plane (run_app, :8000)UI, управление ключами, моделями, пользователямиJWT / cookie
Developer API (run_api, :8002)Ingest, чтение данных, assetsX-API-Key: aic_…

Асинхронный ingest

POST ingest принимается сразу и возвращает request_id + deploy_status: "pending". Запись в latest.db выполняется асинхронно через очередь деплоя. Статус можно проверить через GET /api/v1/ingest/status.

💡 Base URL для ingest берётся из настроек модели в UI (раздел «API-источник»). В prod это обычно https://api-control.<domain>/ext.

Форматы данных

  • CSV — Content-Type: text/csv, тело — raw bytes файла
  • JSON (строки) — массив объектов [{"col": val, …}] или {"rows": […]}
  • JSON (колоночный) — {"col1": [v1, v2], "col2": [v1, v2]} — для init-схемы

Аутентификация

Все запросы к Developer API требуют API-ключ в заголовке.

Заголовок

HTTP Header
X-API-Key: aic_YOUR_KEY_HERE

Альтернатива: Authorization: Bearer aic_YOUR_KEY_HERE

Типы ключей (scope)

scope_typeОписание
modelКлюч привязан к одной модели. model_id в URL не нужен — определяется автоматически.
userКлюч пользователя. Позволяет создавать новые модели (model_create).

Уровни доступа (access_level)

access_levelРазрешённые операции
readGET metadata, status, rows, assets
ingestPOST ingest, upload assets, manage sources
model_createPOST /api/v1/models/ (только user-scoped)
⚠️ Полный ключ (aic_…) показывается только при создании. Сохраните его сразу — восстановить нельзя.

Ограничение таблиц

Ключ может иметь список allowed_tables. Если список задан, ingest в другие таблицы вернёт 403.

Быстрый старт

Загрузите данные в модель за 3 шага.

Шаг 1 — Получить API-ключ

В UI AiControl: откройте модель → «API-ключи» → «Создать ключ». Выберите scope model, access ingest. Скопируйте ключ (aic_…).

Шаг 2 — Отправить данные

curl — snapshot (CSV)
curl — snapshot (JSON)

Шаг 3 — Проверить статус

curl — status

Ответ ingest

{
  "success": true,

  "mode": "snapshot",
  "table": "sales",

Ingest

Загрузка табличных данных в Persistent Store с последующим деплоем в latest.db.

POST /api/v1/ingest/tables/{table_name} ingest

Основной endpoint загрузки данных. Модель определяется по API-ключу.

ПараметрГдеОписание
table_name*pathИмя таблицы (a-z, _, 0-9; не с цифры)
modequerysnapshot stream append
formatquerycsv | json (авто по Content-Type)
filemultipartФайл CSV/JSON (альтернатива raw body)

Режимы ingest

РежимПоведениеТребования
snapshot Полная замена таблицы при каждом POST —
stream Delta upsert по ключевым колонкам upsert_keys — настроить в UI или через control-plane
append Каждый POST добавляет строки (история) В SQLite появится служебная колонка row_id

Models

Метаданные модели, источники данных и компиляция. Модель определяется по API-ключу.

GET /api/v1/models/ read

Метаданные модели (имя, описание, конфиг).

GET /api/v1/models/detail read

Полная детализация: widgets, relationships, processing_config.

POST /api/v1/models/ model_create

Создать новую модель. Требует user-scoped ключ с model_create.

curl

Источники данных (Sources)

GET /api/v1/models/sources read

Список источников (widgets) модели.

GET /api/v1/models/sources/{widget_id} read

Один источник по widget_id.

POST /api/v1/models/sources ingest

Создать новый источник данных.

PATCH /api/v1/models/sources/{widget_id} ingest

Обновить источник (только API-key managed).

Компиляция

POST /api/v1/models/compile ingest

Запустить компиляцию модели (DataCode → latest.db). Асинхронно.

GET /api/v1/models/compile/preview read

Превью склеенного DataCode без выполнения.

Assets

Content-addressed бинарные файлы (изображения, PDF, видео). URI формата asset://{sha256}.

POST /api/v1/assets ingest

Загрузить файл. Возвращает asset://{sha} URI для использования в ingest-данных.

ПолеОписание
file*Бинарный файл (multipart)
kindimage | audio | video | pdf | file
mime_typeMIME (авто из file.content_type)
filenameИмя файла

GET /api/v1/assets read

Список ассетов модели. Query: kind — фильтр по типу.

GET /api/v1/assets/{sha} read

Скачать ассет по SHA-256 хешу.

Ошибки и ограничения

HTTP-коды

КодПричина
401Отсутствует или неверный API-ключ
403Ключ не имеет нужного access_level или таблица не в allowed_tables
404Модель или таблица не найдена
422Ошибка валидации тела запроса
429Stream ingest слишком частый (min_interval_sec)
503Очередь деплоя переполнена (ingest_queue_max_size)

Формат ошибки

JSON
{"detail": "Table 'other' not allowed for this API key"}

Rate limit

Каждый ключ имеет rate_limit_per_min (default 15 req/min). При превышении — 429.

Stream min interval

Для режима stream действует min_interval_sec (default 5 сек) между POST одной таблицы. При нарушении:

429 Response
{"detail": "Stream ingest too frequent; retry in 3s"}

deploy_status: failed

Если деплой в latest.db завершился ошибкой, deploy_status = "failed", поле deploy_error содержит текст ошибки. Данные в Persistent Store сохранены — можно повторить деплой через UI (compile-model).
